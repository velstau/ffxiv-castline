# Castline UI・共有継続の引き継ぎ

更新: 2026-10-25（Asia/Tokyo）

## 目的と完了条件

- Tabler公式UI・アイコンへ統一し、ダークを既定にする。
- 機能をホーム／再生／初期設定／タイムライン管理に整理する。
- 設定済みの場合は毎回設定させず、保存済み範囲を使って再生に進める。
- 初期設定・再生・記録の切り替えで画面共有を再選択しなくてよい。
- OCRの解釈・タイムライン同期・記録の判定・FFLogs生成ロジックは維持する。

## 対象・変更

対象はこのCastlineリポジトリの開発環境。作業開始時は未追跡の `AGENTS.md` だけがあり、これは変更していない。
本番へのデプロイ、コミット、pushはしていない。

- `_build/package*.json`・`scripts/build.mjs`・`scripts/icons.mjs`・`src/app.css`:
  Tabler 1.7.1／Tabler Icons 3.35.0を固定し、CSS/JS/SVG/ライセンスをローカル配布。
- `public/index.html`・`js/app.js`: 同一文書内の画面切り替え、機能ナビ、共有状態、設定済み案内。
  画面ごとにIDを接頭辞で一意化し、旧HTMLは対応するハッシュへ転送。
- `public/js/capture-session.js`・`capture.js`: 共有元を1つだけ保持し、各画面の読み取り停止と全体の共有停止を分離。
- 各画面JS: ID参照の変更、初回だけの初期化、保存データの同一文書内通知。
  再生画面へ戻る際は、動作中のタイムラインエンジンを作り直さない。
- `ocr-client.js`: 設定・再生・記録で同じモデルのWorkerを再利用。
- `pip.js`・`lab.js`: 小窓にもTabler CSSを読み込み、ダークを明示。
- 既存の `.status` はTablerの同名コンポーネントと競合するため `.read-status` に変更。
- 保存先 `castline.regions` 等、既存のデータ形式とギミックSVGは維持。

## 小窓の位置維持（同日追記）

PiPの再表示ボタンで、開いている窓を毎回閉じて作り直していた処理を廃止。既存窓をfocusする。
再生・記録共通のPipとOCR試験で適用。requestWindowにはpreferInitialWindowPlacement:falseを明示。
この値はブラウザの既定値でもあり、これだけで新たな座標保存を実装したわけではない。
サイト側からPiP座標を指定するAPIはないため、閉じた後やブラウザ再起動後の位置復元はブラウザの実装に依存する。

## 討伐後に終了しなかった実戦ログへの対応（同日追記）

利用者ログ: 22:36:42.3敵対リスト消失→22:36:52.9出現→22:36:53.4消失→22:37:09.5手動停止。
状況は「ボスを倒した」と利用者に確認済み。HP値は旧ログにないため、低HP条件を満たさなかった理由は未確定。

修正:
- 戦闘中、敵対リストが1秒以上再確認されるまでは消失待ち時刻をリセットしない。
  短い陽性で待ちが無限に延びるのを防止し、陽性中そのものは終了判定を抑制する。
- 再生画面で敵対リスト消失が1秒以上続く場合、最大1秒間隔で画面中央の範囲をOCR。
  DUTY COMPLETE / COMPLETE / コンプリート等の定型文を別フレームで2回確認したら、HP未読やXML上の中間フェーズでも終了。
  クリア表示なしの敵対リスト消失だけで短時間終了させない（ムービー・移行を保護）。
- 敵対リスト出入りに最終HP・HP観測の古さ・フェーズID、消失後に終了を保留する理由をログに追加。

検証:
- 129件のNodeテスト成功。提供ログの10.6秒消失→0.5秒陽性→再消失を回帰テスト化。
- check-clear-banner-ui.pyでplayer.tickに模擬OCRを渡し、HP未読でもクリア表示2回で終了、表示なしでは継続を確認。
- check-combat-ui.pyのOCRスタブにも新しいscanLines呼び出しを追加。
- 実ゲームのクリア表示を本OCRが読めるかは未検証。実画像なしで改善を保証しない。

## コンテンツ退出後の古いタイムラインとPT募集での誤開始（同日追記）

利用者申告: コンテンツ退出後も前のタイムラインが有効で、PT募集を操作すると戦闘開始・再生になる。
原因: 検出済みコンテンツを消す経路がなく、戦闘扱いになるとコンテンツ名も読み直していなかった。

変更:
- コンテンツ名を戦闘中も1秒間隔で確認する。
- ContentPresenceで確認を管理。確認前/確認が途切れた間は、新たな敵対リスト・開始表示を戦闘開始に使わない。
- 確認不能が6秒継続し、実戦のHP/詠唱（直近HP3秒・詠唱5秒を含む）も確認できなければエンジンを解除。
  自動選択では以前のコンテンツ名・選択項目も消して「コンテンツ情報の確認待ち」へ。
  手動選択したXMLは保持するが、自動再生は停止する。
- 認識失敗を「退出」と断定しない。再確認できれば再生を再準備する。HP/詠唱がある戦闘を名前のOCR失敗だけで消さない。
- Speech.cancelを追加し、ブラウザ音声・再生中のVOICEVOX・合成中で遅れて戻る音声も抑止する。

検証:
- 133件のNodeテスト成功（ContentPresence3件・VOICEVOXキャンセル1件を追加）。
- tools/check-content-presence-ui.pyで認識→名前消失+PT文字陽性でも未開戦→6秒後の旧選択解除→再入場復帰→実戦HPで継続→根拠消失で停止を確認。
- JSエラーなし、git diff --check成功。

限界: 実ゲーム画面は未確認。PT募集に表示された同一のコンテンツ名自体が保存済みの範囲内で高確度認識される場合は、名前だけで画面を区別できない。
再発時は新しい診断ログと、読む範囲に何が映っていたかを確認する。
